# MineKot inspections

`minekot-inspections` provides frozen host-neutral inspection contracts, verified dynamic rule loading, and adapters for Detekt and IntelliJ IDEA. Concrete MineKot checks live in the independently released [`minekot-rules`](../minekot-rules/) repository.

## Modules

- `minekot-inspections-core` defines immutable descriptors, policy, findings, guarded corrections, file-scoped sessions, catalog defaults, and optional semantic capabilities over Kotlin PSI.
- `minekot-inspections-detekt` converts one catalog generation into Detekt rules and deterministic guarded correction rounds.
- `minekot-inspections-idea` exposes one static IntelliJ inspection with packaged batch-report documentation, native previews, suppression mapping, generation draining, and project-scoped lifecycle boundaries.
- `minekot-inspections-loader` exposes PSI-free artifact, manifest, compatibility, cache, and resolver contracts.
- `minekot-inspections-loader-runtime` verifies signed releases, validates thin JARs, and manages content-addressed storage, locks, leases, activation records, and rollback state.

## Host boundaries

`minekot-toolchain` hosts Gradle and Detekt execution. `minekot-toolkit` hosts IntelliJ analysis, UI, activation, and dynamic plugin lifecycle. Both supply host-owned semantic facts through optional core capabilities; rules receive only immutable values and Kotlin PSI valid for the active session.

Downloaded catalogs, visitors, PSI, analysis objects, classloaders, exceptions, and rule-defined values cannot survive a session boundary. Diagnostics and quick fixes retain only core value types.

## Compatibility

SPI major 1 constructors remain frozen. New behavior uses additive capability interfaces. `MineKotInspectionCatalogDefaults` lets newer catalogs declare safe activation, lifecycle, replacement, and severity recommendations while old catalogs remain enabled by default.

Committed API declarations are release-review evidence generated by the Kotlin binary compatibility validator. Run `apiCheck` to reject accidental ABI drift; run `apiDump` only for an intentional reviewed API addition.
